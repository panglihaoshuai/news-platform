# 项目开发规范 (Development Rules)

为了确保 **Global Intel Map** 项目的严谨性与高质量，所有开发活动必须严格遵守以下流程：

## 1. 预研发讨论 (Pre-development Brainstorming)
*   在开始编写任何核心代码前，开发代理（Antigravity）必须与用户进行**头脑风暴**。
*   **内容要求**：调研现有的算法（如当前的 `string-similarity` 语义去重）、参考成熟的开源方案、以及检查本地已有的 Skills。
*   **Skill 引用**：目前本项目拥有 `remotion-best-practices` 技能包，在涉及视频渲染功能时必须强制参考。

## 2. 方案申报与审批 (Planning & Approval)
*   头脑风暴后，必须生成一份正式的**开发方案汇报**。
*   方案应包含：
    *   目标功能描述
    *   技术路径（如：新增 RSS 源、修改数据库 Schema、调整前端 UI 逻辑）
    *   预期的影响范围与潜在风险
*   **原则**：未经用户（USER）显式确认“同意”或“继续”，不得进入编码阶段。

## 3. 单元测试与验证 (Unit Testing)
*   每一个功能单元开发完成后，必须进行严格的**单元测试**。
*   **验证手段**：
    *   运行配套脚本（如 `fetch-rss.ts`, `quick-fetch.ts`）验证后端逻辑。
    *   使用 `browser_subagent` 或手动截图录屏验证前端 UI 与交互。
*   **标准**：测试必须 100% 通过，无报错、无显著性能退化。

## 4. 阶段性汇报 (Phase Reporting)
*   单元测试通过后，向用户提交**阶段性成果报告**。
*   报告应简述已完成的工作、测试结果截图/日志。
*   **申请权限**：只有在汇报完成后，方可申请进入下一阶段的开发。

## 5. 语言限制
*   所有文档（README, RULES, 方案汇报）必须使用**中文**编写，确保逻辑严谨、表述专业。
